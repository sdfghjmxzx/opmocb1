ANIMATION REQUIREMENTS (VERIFIED)
===================================================================================

MOVEMENT ANIMATIONS:
--------------------
Type: Hop animation from square to square
Visual: Figurine "jumps" between tiles
Height: Zoom goes from 1.0 → 1.3 → 1.0 (hop peak at midpoint)
Duration: 0.4 seconds per tile
Path: Sequential hops for each movement in path
Speed Modifier: Based on player speed stat + movement bonuses

ROTATION ANIMATIONS:
--------------------
Type: Rotation while hopping
Visual: Figurine rotates from current angle to target angle
Height: Shares hop with paired movement (or independent hop)
Duration: Scaled by angle delta (45° = 0.3s baseline)
Grouping: Multiple consecutive rotations merge into single animation
Speed Modifier: Based on player speed stat (no hit bonus for rotations)

ATTACK ANIMATIONS:
------------------
Type: Jump animation (1 or 2 hops)
Visual: Figurine jumps in place
First Hop: Always 1.3 zoom (regular attack motion)
Second Hop: Only if attack hits (not skip, not miss)
  - Height scales with damage output percentage
  - Base damage = 20, zoom_base = 1.3
  - Formula: zoom = 1.3 + (damage_percent / 100) * 0.3
  - Examples: 40 dmg (100%) → 1.6, 60 dmg (200%) → 1.9
Skip Animation: Dip instead of hop (zoom 1.0 → 0.8 → 1.0)
Duration: 0.4s base, scaled by damage factor for second hop
Speed Modifier: Not applicable (attack is instant action)

DEFENSE ANIMATIONS:
-------------------
Defend: Rotate sequence
  - Sequence: +45° → 0° → -45° → 0° (repeat 3 times)
  - Total: 6 rotations
  - Duration: 0.2s per rotation = 1.2s total
  
Evade: Shake sequence
  - Sequence: Move right → center → left → center (repeat 3 times)
  - Visual: Horizontal position offset ±0.5 tiles
  - Duration: 0.2s per shake = 1.2s total
  
Counter: Attack-style hop
  - Same as regular attack first hop
  - Single hop, 1.3 zoom
  - Duration: 0.5s
  
Tank: Dip animation
  - Same as skip (zoom 1.0 → 0.8 → 1.0)
  - Duration: 0.3s

PUSH ANIMATIONS:
----------------
Type: Forced movement
Visual: Slide from current position to pushed position
No Hopping: Smooth slide without vertical movement
Duration: 0.3s per tile
Speed Modifier: None (forced action)

DOOM ANIMATIONS:
----------------
Type: Sea tile doom
Visual: Player sinks/fades at sea tile position
Duration: 1.0s
Speed Modifier: None

CORRECT COMBAT FLOW (VERIFIED)
===================================================================================

CRITICAL: This is the EXACT order of operations. DO NOT deviate.

1. ATTACK PHASE
   - Player plans movement, rotation, attack
   - Confirm turn → SNAPSHOT attacker ghost data (position + facing + selected attack)
   - Build and play/queue movement/rotation animations for the attack phase
   - Perform ATTACK-PHASE MISS/SKIP CHECK using:
     * Current attack pattern (from ghost_row/ghost_col/ghost_facing)
     * Defender's CURRENT board position (pre-defense movement)
   - Branch:
     * If SKIP or MISS:
       - No pending_attack is stored
       - Play full attack-phase animation (movement + attack hop/dip)
       - Transition directly to next attack phase
     * If HIT:
       - Store pending_attack (includes all combat data + attack animation info)
       - Only movement/rotation animations play now; attack hop is stored for later

2. DEFENSE PHASE (only if attack phase was not SKIP/MISS)
   - Player plans movement, rotation, defense
   - Confirm turn → SNAPSHOT defender ghost data (planned final position + facing)
   - Build and play/queue defense movement/rotation animations
   - STORE defense animation (do not play attack/defense hops yet)
   - Perform DEFENSE-PHASE MISS CHECK using:
     * Updated attack pattern (from stored attacker snapshot)
     * Defender's GHOST / planned final position after defense movement
   - If MISS here → skip combat calculations, but still play attack/defense animations as miss-resolution

3. COMBAT CALCULATIONS (only if not MISS in either phase)
   - Use ONLY SNAPSHOT / ghost data, NOT live animated state:
     * Attacker position/facing from pending_attack
     * Defender planned final position/facing from defense snapshot
   - First: HIT CHANCE calculation
     * Roll random number vs hit chance
     * If roll fails → MISS (no damage calculations, but attack/defense animations still play as miss)
     * If roll succeeds → HIT (proceed to damage)
   - Second: DAMAGE calculations (only if HIT)
     * Calculate base damage
     * Apply all modifiers (pattern, facing, bounce, DF, Haki, FOV, etc.)
     * Store damage value and hit outcome for animations
   - Third: PUSH/DOOM resolution (logic only)
     * Compute push distance and path
     * Compute sea doom flag if defender would land on sea tile
     * DO NOT yet end the game; just record that doom should occur

4. ATTACK-DEFENSE ANIMATIONS (ALWAYS play, even on MISS)
   - Use stored combat outcome (hit/miss + damage) to drive visuals
   - Play attack animation:
     * If MISS (damage = 0): 1 hop only (no second hop)
     * If HIT (damage > 0): 2 hops
       - First hop: Standard 1.3 zoom
       - Second hop: Scaled by damage (1.3 + damage_percent * 0.3)
   - Play defense animation concurrently:
     * Defend: Rotation sequence
     * Evade: Shake sequence
     * Tank: Dip animation (and still gets +30 stamina from combat logic)
     * Counter: Single hop

5. PUSH ANIMATIONS (only if HIT and push applies)
   - Combat calculations have already determined push_dist and path
   - Queue and play push slide animation for defender
   - During push animation, defender's visual position moves; logical position is updated at animation end

6. DOOM ANIMATIONS (only if combat marked sea doom)
   - If combat logic flagged doom (defender pushed into sea tile):
     * Queue and play doom sink/fade animation at final sea tile position
     * AFTER doom animation completes:
       - Mark player defeated
       - Set game_active = False and winner accordingly

7. NEXT PHASE
   - After ALL queued animations (attack/defense, push, doom) finish:
     - Transition to next attack phase
     - Swap attacker/defender roles

KEY RULES:
----------
- MISS CHECK = "Is defender in attack pattern at all?" (position-based, not hit-chance-based)
- MISS CHECK happens TWICE: After attack phase (using pre-defense position), after defense phase (using ghost/planned position)
- If MISS after attack phase → Skip defense phase entirely; play attack-phase animations only
- If MISS after defense phase or due to hit chance → Skip damage, but still play attack/defense animations as miss-resolution
- Attack/Defense animations ALWAYS play (even on miss)
- Combat calculations ONLY happen if position-based MISS checks pass (defender in pattern)
- HIT CHANCE calculation happens BEFORE damage calculation and uses ghost/snapshot data
- Damage calculation ONLY happens if HIT CHANCE succeeds
- Attack animation uses damage value to determine:
  * 1 hop if MISS (damage = 0)
  * 2 hops if HIT (damage > 0, second hop scaled)
- Push and doom are decided in combat logic but VISUALIZED later via push/doom animations; game over from doom happens AFTER doom animation completes

===================================================================================
ANIMATION QUEUE HIERARCHY
===================================================================================

PHASE EXECUTION ORDER:
----------------------
1. ATTACK PHASE Planning → Confirmation
   ├─ Play Movement Animations (sequentially)
   ├─ Play Rotation Animations (grouped/paired)
   └─ STORE Attack Animation (not played yet)

2. DEFENSE PHASE Planning → Confirmation
   ├─ Play Movement Animations (sequentially)
   ├─ Play Rotation Animations (grouped/paired)
   └─ STORE Defense Animation (not played yet)

3. ATTACK-DEFENSE RESOLUTION
   └─ Play Attack + Defense Animations (CONCURRENTLY)

4. PUSH RESOLUTION (if applicable)
   └─ Play Push Animation (slide)

5. DOOM RESOLUTION (if sea tile)
   └─ Play Doom Animation (sink)

ANIMATION PAIRING RULES:
------------------------
Goal: Minimize total animation time by combining movements and rotations

Rule 1: Rotation Grouping
  - Multiple consecutive rotations on same position → merge into ONE rotation
  - Example: [Rotate 45°, Rotate 45°, Rotate -90°] → Single rotation of 0°
  - This grouped rotation takes same time as single rotation would

Rule 2: Movement-Rotation Pairing
  - A rotation can be paired with the NEXT movement (never previous)
  - Paired = both happen during same hop animation
  - Example: [Move A→B, Rotate 45°, Move B→C]
    → Animation 1: Move A→B (unpaired)
    → Animation 2: Move B→C + Rotate 45° (paired)

Rule 3: Pairing Priority
  - Always try to pair rotations with successor movements
  - If rotation group has no successor movement, play as standalone

OPTIMIZATION ALGORITHM:
-----------------------
Input: List of planned actions
Output: List of animation commands

Step 1: Separate into action types
  - movements = [(row, col), ...]
  - rotations = [degrees, ...]
  - attack/defense = stored separately

Step 2: Identify rotation groups
  - Scan for consecutive rotations
  - Sum their degrees into single rotation
  - Track position (index) in action list

Step 3: Pair rotations with movements
  - For each rotation group:
    - Check if next action is movement
    - If yes: pair rotation with that movement
    - If no: rotation plays standalone

Step 4: Build animation queue
  - For each movement:
    - Check if it has paired rotation
    - Create animation with/without rotation
  - For standalone rotations:
    - Create rotation-only animation

===================================================================================
SPEED MODULATION SYSTEM
===================================================================================

PLAYER SPEED STAT SCALING:
--------------------------
Base Formula:
  animation_duration = base_duration / speed_multiplier
  
Where:
  speed_multiplier = 0.5 + (player.speed / 100) * 0.5
  
Results:
  - Speed 0:   multiplier = 0.5  (animations take 2x time)
  - Speed 50:  multiplier = 0.75 (animations take 1.33x time)
  - Speed 100: multiplier = 1.0  (animations take 1x time - base speed)
  - Speed 200: multiplier = 1.5  (animations take 0.67x time - faster)

MOVEMENT BONUS STACKING:
------------------------
Additional bonuses from movement chains:
  - Facing chain bonus: +10% per chain length (max +50%)
  - Bounce bonus: +10-20% (from bounce detection)
  - Pattern bonus: +10-50% (from pattern mastery)

Combined Formula:
  total_bonus = facing_bonus + bounce_bonus + pattern_bonus
  bonus_multiplier = 1.0 + total_bonus
  final_speed = speed_multiplier * bonus_multiplier

Important: Rotations don't have hit bonuses
  - Rotations use only speed_multiplier
  - If rotation is paired with movement, use movement's bonuses

VISUAL SPECIFICATIONS
===================================================================================

HOP ANIMATION CURVE:
--------------------
Progress: 0.0 → 0.5 → 1.0
Zoom:     1.0 → 1.3 → 1.0

Formula: zoom = 1.0 + hop_height * sin(progress * π)
Where hop_height = 0.3 for standard hop

DIP ANIMATION CURVE:
--------------------
Progress: 0.0 → 0.5 → 1.0
Zoom:     1.0 → 0.8 → 1.0

Formula: zoom = 1.0 - dip_depth * sin(progress * π)
Where dip_depth = 0.2 for standard dip

POSITION INTERPOLATION:
-----------------------
Formula: current_pos = lerp(from_pos, to_pos, progress)
Where: lerp(a, b, t) = a + (b - a) * t

ROTATION INTERPOLATION:
-----------------------
Handle 360° wrapping - take shortest path
Formula:
  diff = to_facing - from_facing
  if diff > 180: diff -= 360
  if diff < -180: diff += 360
  current_facing = from_facing + diff * progress

===================================================================================
ERROR HANDLING & EDGE CASES
===================================================================================

Edge Case 1: No Movement Actions
---------------------------------
If player only rotates and attacks:
  - Rotations play as standalone
  - Attack plays after rotations
  - No movement animations

Edge Case 2: Only Attack/Defense
---------------------------------
If player confirms with only attack/defense:
  - No movement/rotation animations
  - Attack/defense animation plays immediately
  - Stored for resolution phase

Edge Case 3: Animation Interruption
------------------------------------
If game state changes during animation:
  - Complete current animation
  - Skip remaining queue
  - Update to final state

Edge Case 4: Push Out of Bounds
--------------------------------
If push would go out of bounds:
  - Animate up to boundary
  - Stop at edge
  - Apply wall collision effects

Edge Case 5: Concurrent Animations
-----------------------------------
Attack + Defense play simultaneously:
  - Both players animate at same time
  - Synchronize completion
  - Proceed to next phase together

Edge Case 6: Speed Stat Edge Values
------------------------------------
Speed = 0:
  - Multiplier = 0.5 (minimum)
  - Animations take 2x time
Speed = 200+:
  - Multiplier = 1.5+ (scales linearly)
  - Animations can be very fast
