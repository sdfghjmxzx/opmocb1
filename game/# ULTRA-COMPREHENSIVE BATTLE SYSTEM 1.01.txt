## 1. BATTLEFIELD & SETUP

### 1.1 Grid Architecture
- **Dimensions**: 7×7 battlefield, rows 1-7, columns A-G
- **Coordinate System**: 1A (top-left) to 7G (bottom-right), zero-indexed internally as (0,0) to (6,6)
- **Player Starting Positions**:
  - Player 1: 6D (row 5, col 3), facing North (270°)
  - Player 2: 2D (row 1, col 3), facing South (90°)
- **Facing Vectors**: North (0,-1), South (0,1), East (1,0), West (-1,0), NE (1,-1), NW (-1,-1), SE (1,1), SW (-1,1)

### 1.2 Wall System Architecture
- **Definition**: Diagonal edge between two orthogonally adjacent squares (a,b) and (a+1,b+1)
- **Placement**: Walls exist *between* squares, not on squares
- **Bidirectional Blocking**: Blocks movement both directions
- **Wall Types**:
  - **Border Walls**: Permanent invisible walls at map edges
  - **Internal Walls**: 3-5 randomly placed walls within map boundaries (rendered as diagonal edge graphics)

### 1.3 Special Tile Placement
- **Location**: Special tiles spawn *on* squares (except Sea Tiles which spawn on edges)
- **Exclusivity**: **Only ONE special tile per square** (no stacking)
- **Spawn Timing**: Initial spawn before first turn; per-turn spawns at start of each Attack Phase
- **No Priority Order**: Simultaneous placement, conflicts resolved randomly

## 2. STAT SYSTEM

### 2.1 Stat Definitions (0-100 Scale)
All stats are **integers** ranging from **0 to 100**. No stat budget exists—all can be maxed.

**Primary Stats** (affect pools and direct combat):
- `strength`: Health pool, damage dealt
- `defense`: Health pool, damage taken
- `speed`: Stamina pool, hit chance
- `reaction`: Stamina pool, evasion chance

**Secondary Stats** (efficiency multipliers):
- `endurance`: Stamina recovery, cost reduction (20% of old system)
- `willpower`: Health pool, stamina pool, damage reduction (10% of old system)

**Combat Instinct** (uncancelable offense):
- `combat_instinct`: Hit chance bonus vs all opponents
- Nullifies opponent's combat_instinct (difference-based)

**Aura** (uncancelable power):
- `aura`: Damage multiplier, minor hit chance bonus
- Nullifies opponent's willpower (difference-based)

**Haki Stats** (powerful but expensive):
- `haki_armament`: 0-100 (cheapest, +30% dmg/def)
- `haki_observation`: 0-100 (medium, +30% hit/def chance, -15% stamina cost)
- `haki_conqueror`: 0-100 (expensive, -30% opponent stats)

**Devil Fruit Stat**:
- `devil_fruit_mastery`: 0-100 (governs DF stamina, recovery, cost reduction, type advantage effectiveness)

### 2.2 Pool Calculation Formulas

**Health Pool:**
```python
PrimarySum = strength + defense

MaxHealth = PrimarySum × 3.0 \
          + PrimarySum × (endurance / 100) × 0.667 \
          + PrimarySum × (willpower / 150) × 0.5
```

**Stamina Pool:**
```python
PrimarySum = speed + reaction

MaxStamina = PrimarySum × 3.0 \
           + PrimarySum × (endurance / 100) × 0.667 \
           + PrimarySum × (willpower / 150) × 0.5
```

**Haki Stamina Pool:**
```python
TotalStats = strength + defense + speed + reaction + endurance + willpower

MaxHakiStamina = TotalStats × 0.5  # Max 300 at 600 total stats
CurrentHakiStamina = MaxHakiStamina  # Reset at battle start
```

**Devil Fruit Stamina Pool:**
```python
MaxDFStamina = (devil_fruit_mastery × 2.0) + (devil_fruit_mastery × (aura / 150) × 0.5)

# UI Display Normalization (always shows 0-100):
DisplayedDFStamina = (CurrentDFStamina / MaxDFStamina) × 100
CurrentDFStamina = (DisplayedDFStamina / 100) × MaxDFStamina
```

### 2.3 Recovery Formulas

**Stamina Recovery (per turn start):**
```python
PrimarySum = speed + reaction

if PrimarySum <= 100:
    Exponent = 1.1 + 0.002 × (PrimarySum - 50)
else:
    Exponent = 1.2 + 0.004 × (PrimarySum - 100)

BaseK = 0.000304 × (50 / PrimarySum) ** Exponent

RecoveryRate = 0.02 + (BaseK × endurance × 0.667) + (BaseK × willpower × 0.333)

StaminaRecovery = MaxStamina × RecoveryRate
HealthRecovery = MaxStamina × RecoveryRate × 0.5  # Half rate
```

**Haki Stamina Recovery:**
```python
RestorationRate = 0.20 × (TotalStats / 300)  # 20% per turn at 300 stats

HakiRestoration = MaxHakiStamina × RestorationRate
```

**Devil Fruit Stamina Recovery:**
```python
DFStaminaRecovery = MaxDFStamina × (devil_fruit_mastery × 0.002)
# At 0 mastery: 0% recovery per turn
# At 50 mastery: 10% of max pool
# At 100 mastery: 20% of max pool
```

**Devil Fruit Stamina Cost Reduction:**
```python
ActualDFCost = BaseDFCost × (1 - (devil_fruit_mastery × 0.003))
# At 0 mastery: 0% reduction (cost × 1.0)
# At 50 mastery: 15% reduction (cost × 0.85)
# At 100 mastery: 30% reduction (cost × 0.70)
```

## 3. TURN STRUCTURE & PHASES

### 3.1 Standard Turn Structure
The core turn sequence remains:
```
Player 1 Attack Phase → Player 2 Defense Phase → Player 2 Attack Phase → Player 1 Defense Phase → Repeat
```

### 3.2 Interactive Turn System Conditions

**Condition 1: Attacker Skip/Rest Action**
If the attacking player chooses to **skip/rest** during their Attack Phase, the defending player's Defense Phase is automatically skipped.

**Definition of "Skip/Rest":**
"Skip/Rest" is defined as the attacking player **confirming their planning phase without selecting any attack action** (Quick, Normal, Heavy, or Special).

**Skip/Rest Consequences:**
- The attacking player's turn ends immediately upon confirmation
- The defending player's Defense Phase is **skipped entirely**
- The turn order advances directly to the **next Attack Phase**, with the defending player becoming the new attacker
- All standard phase-start effects still occur:
  - Both players recover stamina per v5.1 recovery rules
  - Both players recover Haki stamina per v5.1 rules
  - Status effect durations advance
  - Turn counter increments

**Stamina Cost of Skip/Rest:**
No stamina cost is incurred for choosing to skip/rest. The action is free.

**Condition 2: Attack Pattern Miss**
If, at the start of the defending player's Defense Phase, the defender is **not currently standing on any square** that is part of the attacking player's final attack pattern, the Defense Phase is skipped.

**Definition of "Attack Squares":**
The "attack squares" are defined as all coordinate positions that satisfy the final attack pattern calculated from the attacker's **confirmed position and facing**. This pattern is **locked** at the moment the attacker confirms their planning phase and does not change thereafter.

**Miss Detection Process:**
1. Attacker confirms planning phase with an attack action
2. Defender's **immediately preceding movement actions** (if any) are resolved from their last turn
3. **At the start of the Defense Phase**, system checks defender's current position against the **static attack pattern** coordinates
4. If defender's position is **not** in the pattern: Defense Phase is skipped
5. If defender's position **is** in the pattern: Defense Phase proceeds normally

**Miss Consequences:**
- If Defense Phase is skipped due to miss:
  - The defending player **does not** perform any defensive actions
  - The turn order advances directly to the **next Attack Phase**, with the defending player becoming the new attacker
  - All standard phase-start effects still occur:
    - Both players recover stamina per v5.1 recovery rules
    - Both players recover Haki stamina per v5.1 rules
    - Status effect durations advance
    - Turn counter increments

### 3.3 Phase Skipping Priority
If **both** conditions are true (attacker skipped AND defender not in attack squares), the Defense Phase is skipped **once**. No double-skipping occurs.

### 3.4 No Redefinition of Combat Phases
The Attack Phase and Defense Phase still exist in the game logic. They are simply **executed with no player actions** when skipped. All automatic effects (recovery, duration ticks) still process.

### 3.5 Integration with Existing Systems

**Stamina Recovery During Skipped Phases:**
- Normal Stamina Recovery: Occurs at start of **each player's turn** regardless of skip status
- Haki Stamina Recovery: Occurs at start of **each player's turn** regardless of skip status
- DF Stamina Recovery: Occurs at start of **each Attack Phase** regardless of skip status

**Status Effect Duration During Skipped Phases:**
Status effect durations **advance by 1 turn** during any skipped phase. Effects expire normally when their duration reaches zero.

**Pattern Memory During Skipped Phases:**
The Facing Direction Effect chain and Pattern Mastery bonuses **do not reset** due to phase skipping. They persist until the player's next active planning phase where an attack/defense is executed.

**Turn Counter During Skipped Phases:**
The turn counter increments by **1** for each phase (Attack or Defense) whether executed or skipped. The game tracks total elapsed phases for effect durations and recovery calculations.

### 3.6 Planning Mode
- **Activation**: Click player character to enter planning mode
- **Ghost State**: All planning on ghost copy; actual position unchanged until confirmation
- **Action Queue**: Actions queued in exact selection order
- **Stamina Tracking**: Real-time total stamina cost calculation
- **Undo/Redo**: Full history maintained; undo removes most recent action and reverts ghost state
- **Terminal State**: Attack/defense action terminates planning (only Confirm/Cancel/Undo available)

### 3.7 Devil Fruit Planning Phase Flow
**Allowed Action Sequence:**
```python
1. MOVEMENT: Any number of movements (8 directions, stamina cost applies)
2. ROTATION: Any number of 45° rotations (5 stamina attack / 20 stamina defense)
3. CREATION: ONE wall OR ONE trap tile (DF stamina cost)
4. MOVEMENT: Additional movements allowed after creation
5. ATTACK/DEFENSE: Select ONE attack or defense action (becomes terminal)
6. ALLOYS: Apply DF and/or Haki alloys to the selected action
7. CONFIRM/CANCEL/UNDO: Finalize or modify plan

# Once step 5 (attack/defense) is performed:
# - NO further movement, rotation, or creation
# - ONLY alloys, confirm, cancel, undo are allowed
```

### 3.8 Per-Turn Limits
- **Attacks**: Exactly ONE per turn (Quick/Normal/Heavy/Special)
- **Defenses**: Exactly ONE per turn (Evade/Defend/Counter)
- **Creations**: Exactly ONE per turn (Wall OR Tile, not both)
- **Alloys**: Any number can be applied to the single attack/defense
- **Movements**: No hard limit beyond stamina constraints
- **Rotations**: No hard limit beyond stamina constraints

### 3.9 Player Decision Implications

**Strategic Skip Decision:**
A player may choose to skip/rest for strategic reasons:
- To recover stamina without risk
- To force opponent's phase to skip, denying them defense bonuses
- To preserve positioning

**Automatic Miss Handling:**
A player does **not** choose to miss. The miss is determined automatically by the system based on final attack pattern geometry. The attacker still expends stamina for the attack action, but the defender's phase is skipped.

**Information Availability:**
The attacker does **not** see whether their attack will hit or miss before confirming. The miss determination occurs after confirmation, during the transition to the Defense Phase.

### 3.10 Special Attack Pattern Considerations

**Special Attack Miss Rule:**
Special attacks follow the same miss detection as standard attacks. If the defender's position is not within the final Special attack pattern coordinates, the Defense Phase is skipped.

**Map Creation and Attack Miss:**
A player can create walls or tiles that cause the defender to move out of the attack pattern. If the defender moved out of the pattern **during their previous turn** (as attacker), the miss detection will correctly identify this and skip the Defense Phase.

### 3.11 Conflict Resolution

**Simultaneous Skip Conditions:**
If an attacker skip and a defender not-in-pattern condition both occur in the same turn transition, the Defense Phase is skipped **once**. The turn advances normally.

**Interaction with Parley System:**
If an attack is "Excellent" (parley eligible) but the defender is not in the attack pattern, the parley window **does not trigger** because the Defense Phase is skipped. The attacker does not get a follow-up turn.

### 3.12 Final Turn Flow with Interactive System
```
Scenario A: Normal Attack
Player 1 Attack Phase → Attack executes → Defender in pattern → Player 2 Defense Phase → Player 2 Attack Phase

Scenario B: Attacker Skip
Player 1 Attack Phase (Skip) → No attack executed → Defense Phase SKIPPED → Player 2 Attack Phase

Scenario C: Attack Miss
Player 1 Attack Phase → Attack executes → Defender NOT in pattern → Defense Phase SKIPPED → Player 2 Attack Phase
```

## 4. BOUNCE SYSTEM (REVISED WITH SCALING & CONTINUITY)

### 4.1 Core Architecture
- **Trigger**: Requires Entry Tile → Wall Tile → Exit Tile in three consecutive actions
- **Vector-Based**: Only entry and exit direction vectors determine validity (path between irrelevant)
- **Silent Failure**: Invalid bounce resolves as standard movement with no penalty
- **Scaling Bonuses**: Bounce bonuses scale progressively from Move 1 (exit) through Move 5+ (cap)

### 4.2 Bonus Scaling Table

| Move # | Stamina Discount | Hit Chance Bonus (Attack) | Dodge Chance Bonus (Defense) |
|--------|------------------|---------------------------|------------------------------|
| 1 (Exit Tile) | **-10%** | **+10%** | **+10%** |
| 2 | **-15%** | **+12.5%** | **+12.5%** |
| 3 | **-20%** | **+15%** | **+15%** |
| 4 | **-25%** | **+17.5%** | **+17.5%** |
| 5+ (Cap) |  **-30%**  |  **+20%**  |  **+20%**  |

### 4.3 Cardinal Bounce (Linear Rebound)
- **Entry**: Must approach wall tile from exact opposite direction of wall's blocking face
  - North wall → Enter from South (moving North)
  - East wall → Enter from West (moving East)
- **Exit**: Must exit by moving forward in same direction as entry
- **Continuation**: **Every subsequent move** must be the **exact same cardinal direction** as the exit
- **Chain Break**: Moving in any other direction (including diagonals) terminates the bounce state
- **Failure**: Exit tile occupied, out of bounds, or blocked by separate wall → bounce fails, player remains in wall tile

**Example**: Bounce off a **South wall** → Enter moving **North** → Exit to **North** → Chain requires **all future moves to be North**. Moving NE, NW, or any other direction breaks the chain.

### 4.4 Diagonal Bounce (Angular Deflection)
- **Entry**: Must enter from valid diagonal direction creating approach angle
- **Exit**: Must exit in permissible deflection vector (90° or 270° rotation of entry vector)
- **Continuation**: Must continue moving **diagonally away from the wall** in either valid diagonal direction for that wall orientation
  - **Horizontal Wall**: Exit NE or NW → Continue with **NE** or **NW** only
  - **Vertical Wall**: Exit NE or SE → Continue with **NE** or **SE** only
- **Chain Break**: Moving cardinally or diagonally **toward** the wall breaks the chain
- **Red Arrow Rule**: Any exit not in permissible set = no bounce
- **Internal Wall Rule**: Cannot exit diagonally into wall's shielded interior

**Example (Horizontal Wall South)**: Exit **NE** or **NW** → Continue with **NE** or **NW** only. Moving SE, SW, or any cardinal direction breaks the chain.

### 4.5 Multi-Bounce Chain Continuity (Rule Update5)

#### **4.5.1 Single-Type Continuity**
A bounce chain can continue through **multiple sequential bounces** without breaking if:
- **Diagonal chain** continues with **new diagonal bounce**
- **Cardinal chain** continues with **new cardinal bounce**

#### **4.5.2 Directional Lock Update**
Each new bounce **updates the allowed directions** to follow the newest wall's rules.

#### **4.5.3 Bonus Progression**
The chain's move counter **continues incrementing** through all bounces and movements.

#### **4.5.4 Chain Type Transition Rules**
- **Diagonal → Cardinal**: **BREAKS CHAIN** (except on corner tiles)
- **Cardinal → Diagonal**: **BREAKS CHAIN** (except on corner tiles)
- **Same Type → Same Type**: **CONTINUES CHAIN** (moves count, bonuses scale)

### 4.6 Corner Tile Special Rules (Positions 1A, 1G, 7A, 7G)

#### **4.6.1 Type Transition Exception**
On a corner tile **ONLY**, you may:
- Transition from **Diagonal → Cardinal** chain **without breaking**
- Transition from **Cardinal → Diagonal** chain **without breaking**
- **Requirements**:
  1. You must be **physically on the corner square**
  2. You must perform a **valid bounce** off one of the corner walls
  3. The chain continues with **updated directional lock** from the new bounce

#### **4.6.2 Example: Corner Transition**
```
Position 1A (top-left corner), facing SE
1. Diagonal bounce off North wall → Exit SE (Move 1: -10%, +10%)
2. Move SE → SE → (Chain builds...)
3. Reach East wall at position 1G (corner)
4. Bounce off East wall → Choose Cardinal bounce South
5. Chain CONTINUES (corner exception!) → Now locked to South only
6. Move South (chain continues from previous move count)
```

### 4.7 Chain Break Consequences

#### **Stamina Discounts**
- **Retained**: All moves already executed in the chain **keep their earned discounts**
- **Lost**: Future moves after the break **no longer receive discounts**

#### **Hit/Dodge Bonus**
- **Retained**: Only if your **terminal attack/defense is the immediate next action** after a **valid chain of any length**
- **Lost**: If you break the chain **before** executing your terminal action, you **forfeit the hit/dodge bonus**

**Example**: Exit (Move 1, -10%/+10%) → Move 2 (-15%/+12.5%) → **Break with cardinal move** → Attack: You keep the discounts on Moves 1-2, but **attack gets no bonus** because chain was broken.

### 4.8 Defense Phase Application

During your **defense phase**, the bounce bonuses convert:

| Bonus Type | Application | Scaling |
|------------|-------------|---------|
| **Stamina Discount** | **All defensive movements** | Same progression (10% → 30%) |
| **Hit Chance → Dodge** | **Adds to dodge chance** | Same values (10% → 20%) |
| **Damage Reduction** | **None** | Not applicable |

**Result**: A defender who chains 5+ bounce moves gains **+20% dodge chance** against the incoming attack and **-30% stamina cost** on all defensive movements.

### 4.9 Special Rules

#### **Rotations**
- **Cost**: Always eligible for **current chain's stamina discount**
- **Chain Impact**: **Never break** bounce chains (direction-agnostic)
- **Bonus Contribution**: Rotations **do not count** toward the 5-move progression

#### **Standing Still**
- **Chain Status**: **Paused, not broken**
- **Stamina Discount**: **Not consumed** (no movement, no cost)
- **Bonus Retention**: Maintains current progression level (e.g., "stuck" at Move 3 bonuses until you move again)

#### **Ghost Facing Independence**
- Bounce activation and continuation **do not modify** ghost facing
- Facing Direction chains **operate separately** and can break/be maintained independently

### 4.10 Multi-Bounce Chain Examples

#### **4.10.1 Pure Diagonal Chain**
```
Start: 5D, facing NE
1. Bounce off South wall → Exit NE (Move 1: -10%, +10%)
   Lock: NE or NW (away from South wall)
2. Move NE (Move 2: -15%, +12.5%)
3. Hit East wall → Valid diagonal entry from SW
   Bounce off East wall → Exit NW (Move 3: -20%, +15%)
   Lock UPDATES: NW or SW (away from East wall) ← Chain continues!
4. Move NW (Move 4: -25%, +17.5%)
5. Attack: +17.5% hit bonus
```

#### **4.10.2 Pure Cardinal Chain**
```
Start: 4D, facing North
1. Bounce off South wall → Exit North (Move 1: -10%, +10%)
   Lock: North only
2. Move North (Move 2: -15%, +12.5%)
3. Hit North wall → Bounce off North wall → Exit South (Move 3: -20%, +15%)
   Lock UPDATES: South only ← Chain continues!
4. Move South (Move 4: -25%, +17.5%)
5. Attack: +17.5% hit bonus
```

#### **4.10.3 Chain Break Examples**
```
Diagonal → Cardinal (NON-CORNER):
1. Diagonal bounce → Exit NE (chain starts)
2. Move NE (chain continues)
3. Hit East wall → Attempt Cardinal bounce North
   RESULT: CHAIN BREAKS (invalid type transition)

Cardinal → Diagonal (NON-CORNER):
1. Cardinal bounce → Exit North (chain starts)
2. Move North (chain continues)
3. Hit wall → Attempt Diagonal bounce NE
   RESULT: CHAIN BREAKS (invalid type transition)
```

## 5. FACING DIRECTION EFFECT SYSTEM

### 5.1 Core Architecture
- **Ghost Facing**: Persistent orientation state variable during planning
- **Chain Definition**: Contiguous movement actions where each direction exactly matches ghost's current facing vector
- **Atomic Bonus**: Bonus is property of the chain, applied uniformly to all members

### 5.2 Chain Formation & Scaling
- **Formula**: `Chain_Bonus = min(10% × chain_length, 50%)`
- **Retroactive Application**: When chain length increases, all existing members update:
  - After 1 move: 10% on Move 1
  - After 2 moves: 20% on Moves 1-2
  - After 5+ moves: 50% on ALL moves in chain

### 5.3 Chain Break Conditions
- **Hard Break** (Non-Facing Movement):
  - Breaking move receives 0% bonus
  - Does not start new chain (dead action)
  - Preceding chain locks at current bonus level
  - Ghost facing updates to breaking move's direction
  - New chain can only begin on subsequent action
- **Terminal Break** (Attack/Defense):
  - Explicitly terminates any active chain
  - Receives current Chain_Bonus of preceding chain
  - Becomes final planned action; forces terminal state

### 5.4 Rotation Rules
- **Unlimited Quantity**: Any number of rotations before/between/after movements
- **Chain Preservation**: Rotations never break chains
- **State Update**: Immediately changes ghost facing for subsequent action evaluation
- **Stamina Cost**: 5 stamina (attack) or 20 stamina (defense) per 45° turn
- **Cost Modification**: Affected by bounce bonuses (30% discount) but NOT by Facing Direction Effect

## 6. MOVEMENT SYSTEM

### 6.1 Basic Movement Rules
- **Range**: Any tile with Chebyshev distance 1 (8 directions)
- **Blockers**:
  - Opponent's position (cannot occupy same tile)
  - Walls between tiles (bidirectional blocking)
  - Border edges (treated as indestructible walls)
  - Unpassable tiles (blocks movement)
- **Wall Parallel Movement**: Allowed if movement direction is parallel to wall edge
- **Maximum**: No hard limit; constrained by stamina

### 6.2 Stamina Costs
- **Base Cost**: 15 stamina/move (attack phase), 30 stamina/move (defense phase)
- **Modifiers**:
  - Facing Direction Chain: `-Chain_Bonus` (multiplicative)
  - Bounce Status: `×0.7` (30% discount)
  - Positional Penalties: Defense actions in FOV/Non-FOV zones get +25% or +50% stamina cost

## 7. ATTACK SYSTEM

### 7.1 Attack Types & Base Stats
| Attack Type | Range | Base Damage | Base Stamina Cost | Hit Chance Modifier | Damage Modifier |
|-------------|-------|-------------|-------------------|---------------------|------------------|
| Quick | 1 | **20** | 10 | **+25%** | **-50%** |
| Normal | 2 | **20** | 20 | **0%** | **0%** |
| Heavy | 3 | **20** | 30 | **-25%** | **+50%** |
| Special | Custom | Variable | 5-40 | Variable | Variable |

**Note**: All attack types use universal base damage of **20**. Attack type modifiers are applied to achieve final damage of 10/20/30.

### 7.2 Special Attack Definition
Each Devil Fruit defines its Special attacks in the format:
```python
"special_attacks": {
    "attack_name": {
        "pattern": [[x1,y1], [x2,y2], ...],  # Relative coordinates from attacker (0,0)
        "base_damage": integer,
        "base_stamina_cost": integer,
        "base_hit_chance": integer
    }
}
```
- Pattern coordinates must be forward-facing (y > 0)
- Maximum pattern size: 7×7 squares (full battlefield)

### 7.3 Attack Selection Limit
- During a planning phase, a player may select **exactly one** attack action (Quick, Normal, Heavy, or Special)
- Once an attack is selected, no further movement, rotation, or creation actions are allowed. Only alloys may be applied afterward

### 7.4 Cardinal Attack Patterns
- **Shape**: 3 tiles wide × range tiles deep rectangular prism
- **Orientation**: North/South = horizontal width; East/West = vertical width
- **Coverage**: All squares in rectangle are valid targets
- **Range**: Quick = 1 tile deep, Normal = 2 tiles deep, Heavy = 3 tiles deep

### 7.5 Diagonal Attack Patterns
- **Coordinate System**: Player at position P = (pₓ, pᵧ), facing vector F = (fₓ, fᵧ) where fₓ, fᵧ ∈ {-1, 0, 1}
- **Set-Based Formula**: Attack patterns use explicit relative coordinate sets
- **Quick Attack (3 tiles)**:
  - S(1) = { (fₓ, fᵧ), (fₓ, 2fᵧ), (2fₓ, fᵧ) }
- **Normal Attack (5 tiles)**:
  - S(2) = S(1) ∪ { (2fₓ, 2fᵧ), (3fₓ, fᵧ) }
- **Heavy Attack (8 tiles)**:
  - S(3) = S(2) ∪ { (fₓ, 3fᵧ), (2fₓ, 3fᵧ), (3fₓ, 2fᵧ) }
- **Final Tile Coordinates**: Tiles = { (pₓ + x, pᵧ + y) | (x, y) ∈ S(k) }
- **Example (NW facing, fₓ=-1, fᵧ=-1)**:
  - Quick: { (-1,-1), (-1,-2), (-2,-1) } = 3 tiles
  - Normal: + { (-2,-2), (-3,-1) } = 5 tiles total
  - Heavy: + { (-1,-3), (-2,-3), (-3,-2) } = 8 tiles total

### 7.6 Wall Blocking for Attacks

**Cardinal Attacks**:
- **North**: Blocks all squares with y ≥ b+1
- **South**: Blocks all squares with y ≤ b
- **East**: Blocks all squares with x ≥ a+1
- **West**: Blocks all squares with x ≤ a

**Diagonal Attacks** (Rule-Based System):
Diagonal attack wall blocking uses empirically-verified pattern-based rules rather than geometric formulas. The system:

1. **Coordinate System**:
   - `dx` = left/right offset (row delta)
   - `dy` = forward/backward offset (column delta)
   - For NE/SE: forward = increasing column (positive dy)
   - For NW/SW: forward = decreasing column (negative dy)

2. **Wall Offset Adjustments**:
   - **Vertical walls + NE/SE facing**: Apply +1 column offset to wall position
   - **Horizontal walls + SE/SW facing**: Apply +1 row offset to wall position
   - These adjustments correct visual anchoring mismatches between player and wall positions

3. **dx Sign Convention**:
   - **NE/SE facing**: Walls to the left have **negative dx**
   - **NW/SW facing**: Walls to the right have **positive dx**
   - Sign reflects spatial orientation relative to facing direction

4. **Rule Lookup Process**:
   - Calculate local vector (dx, dy) from player to wall with offset adjustments
   - Transform to facing-relative coordinates
   - Look up blocked indices in rule table: `(facing, wall_type, dx, dy) → {blocked_indices}`
   - Each rule maps to specific heavy pattern tile indices (0-7)

5. **Pattern Index Order** (Heavy Attack):
   For facing vector F = (fx, fy):
   - Index 0: (fx, 0)
   - Index 1: (0, fy)
   - Index 2: (fx, fy)
   - Index 3: (2fx, fy)
   - Index 4: (fx, 2fy)
   - Index 5: (2fx, 0)
   - Index 6: (0, 2fy)
   - Index 7: (2fx, 2fy)

6. **Rule Table Structure**:
   - 24 verified examples (12 NE, 12 NW)
   - SE/SW reuse NE/NW rules with flipped dx sign
   - Each rule specifies wall type (vertical/horizontal) and exact dx/dy pair
   - Blocked indices correspond to pattern tiles obstructed by the wall

7. **Hierarchical Blocking**:
   - First apply heavy attack blocking rules
   - Then reduce to normal/quick attack patterns
   - Only tiles blocked in BOTH heavy and reduced patterns remain blocked

### 7.7 Hit Chance Formula
```python
# BASE HIT CHANCE: 66% (CORRECTED)

# Step 1: Attack type modifier
hit_mod = 0.0
if attack_type == "quick": hit_mod += 0.25
if attack_type == "heavy": hit_mod -= 0.25

# Step 2: Defense type modifier (if defense phase)
if defense_type == "evade": hit_mod -= 0.25
if defense_type == "defend": hit_mod += 0.25
if defense_type == "counter": hit_mod += 0.25

# Step 3: Universal defensive dodge bonus (defense phase only)
# These bonuses become dodge chance for defender
dodge_mod = 0.0
if is_defense_phase:
    dodge_mod += min(FacingBonus, 0.15)        # Max 15%
    dodge_mod += min(BounceBonus × 0.4, 0.10)  # Max 10% (40% of 25% cap)
    dodge_mod += min(PatternBonus × 0.5, 0.125) # Max 12.5% (50% of 25% cap)

# Step 4: Stat nullification (purely difference‑based)
hit_mod += (speed - reaction) × 0.15%
hit_mod += (combat_instinct - opp_ci) × 0.15%
hit_mod += (aura - willpower) × 0.10%

# Step 5: FOV Positional Bonus (Attack Phase Only - see Section 31)
fov_bonus = 0.0  # Default
if not is_defense_phase:
    # Determine attacker's FOV layer containing defender
    fov_layer = get_fov_layer(attacker.facing, attacker_position, defender_position)
    if fov_layer == "FOV": fov_bonus = 0.0      # Frontal attack, no bonus
    if fov_layer == "Periphery": fov_bonus = 0.10  # Flanking bonus (+10%)
    if fov_layer == "Behind": fov_bonus = 0.30     # Rear attack bonus (+30%)
    
    # Observation Haki Override: Defender negates FOV bonus
    if defender_observation_haki_active:
        fov_bonus = 0.0  # Negated
hit_mod += fov_bonus

# Final calculation
FinalHitChance = 0.66 + hit_mod - dodge_mod  # 66% base
FinalHitChance = max(0.05, min(0.95, FinalHitChance))  # Clamp [5%, 95%]
```

### 7.8 Damage Formula
```python
# BASE DAMAGE: Universal 20 for all attack types (CORRECTED)

# Step 1: Base damage with attack/defense modifiers
damage_mod = 0.0
if attack_type == "quick": damage_mod -= 0.50   # -50%
if attack_type == "heavy": damage_mod += 0.50   # +50%

if defense_type == "evade": damage_mod += 0.50  # +50%
if defense_type == "defend": damage_mod -= 0.50 # -50%
if defense_type == "counter": damage_mod += 0.50 # +50%

base_damage_mod = BaseDamage × (1.0 + damage_mod)
# Quick: 20 × 0.5 = 10, Normal: 20 × 1.0 = 20, Heavy: 20 × 1.5 = 30

# Step 2: Stat multipliers
StatModifier = 1.0 + (strength - defense) × 0.0015  # 100 diff = +15%

AuraWillpowerModifier = 1.0 + (aura - willpower) × 0.0015   # Purely difference-based

# Devil Fruit component
DFComponent = (1.0 + (effective_strength - defender.defense) × 0.0015 
                   - (original_strength - defender.defense) × 0.0015)

stat_multiplier = StatModifier × AuraWillpowerModifier × DFComponent

# Step 3: Position bonuses (offensive) or damage reduction (defense)
offensive_multiplier = 1.0
defensive_multiplier = 1.0

if is_defense_phase:
    # Defender converts bonuses to damage reduction
    dmg_reduction = 0.0
    dmg_reduction += min(FacingBonus, 0.15)        # Max 15%
    dmg_reduction += min(BounceBonus × 0.4, 0.10)  # Max 10%
    dmg_reduction += min(PatternBonus × 0.5, 0.125) # Max 12.5%
    offensive_multiplier = 1.0 - dmg_reduction
else:
    # Attacker uses bonuses offensively
    bonus_sum = min(FacingBonus, 0.15) + min(BounceBonus × 0.4, 0.10) + min(PatternBonus, 0.25)
    offensive_multiplier = 1.0 + bonus_sum

# Step 4: Defensive modifiers
if defense_alloy_active:
    defensive_multiplier *= 0.90  # -10% damage

if armament_haki_active:
    defensive_multiplier *= (1.0 - 0.30 × effectiveness)  # Up to -30%

# Final damage calculation
FinalDamage = base_damage_mod × stat_multiplier × offensive_multiplier × defensive_multiplier
FinalDamage = max(1, int(FinalDamage))  # DAMAGE FLOOR: Minimum 1
```

## 10. PATTERN MASTERY SYSTEM

### 10.1 Pattern Definitions & Bonuses
- **Rotation Rule**: All patterns ignore rotation actions during detection
- **Circle Pattern** (Scalable): Contiguous movement around opponent ring (after entry)
  - 4 squares: +20% hit chance
  - 5 squares: +25% hit chance
  - 6 squares: +30% hit chance
  - 7 squares: +35% hit chance
  - 8 squares: +40% hit chance

  - Maximum bonus: 60% at 16 squares
- **Zig-Zag Pattern**:
  - Level 1 (Tight): NE → NW → NE → +15% hit, +5% stamina reduction
  - Level 2 (Wide): NE,NE → NW,NW → +10% hit, +10% stamina reduction
  - Level 3 (Triple): NE,NE,NE → NW,NW,NW → +5% hit, +15% stamina reduction
- **Knight's Tour Pattern**: 3-step L-move (two in one cardinal direction, one perpendicular cardinal) → +15% damage
  - Examples: N,N,E or N,N,W or E,E,N or E,E,S or S,S,E or S,S,W or W,W,N or W,W,S
- **Spearhead Pattern** (Scalable, Levels 1-5): Two types, rotation-agnostic
  - **Diagonal Type**: diagonal → cardinal → diagonal on other side (e.g., NW, N, NE)
  - **Cardinal Type**: cardinal → diagonal (toward side) → orthogonal cardinal (e.g., N, NW, W)
  - Level 1 (3 moves): +10% hit, +10% damage
  - Level 2 (6 moves, 2 consecutive spearheads of same type): +20% hit, +20% damage
  - Level 3 (9 moves, 3 consecutive spearheads of same type): +30% hit, +30% damage
  - Level 4 (12 moves, 4 consecutive spearheads of same type): +40% hit, +40% damage
  - Level 5 (15 moves, 5 consecutive spearheads of same type): +50% hit, +50% damage

### 10.2 Pattern Rules
- **Detection**: Automatic during planning phase
- **Visual Feedback**: Purple flash on confirm
- **One-Time Use**: Bonus granted once per planning phase
- **Memory**: Persists across turns; disrupted by Push

### 12.4 Nullification Rules (Alloy Combat)

**Rule:** Haki nullification **only occurs** when **both players use Haki on the same action**.

```python

    # Attacker gets bonus, Defender gets nothing
else if Defender.HA > Attacker.HA:

    # Defender nullifies attacker completely
else:
```

### 14.3 Counter-Attack Resolution
**NEW COUNTER MECHANICS (CORRECTED)**:
1. Defender takes damage **FIRST** using defense damage formula (with Counter +50% damage modifier)
2. If defender survives (health > 0), counter-attack triggers:
   - Counter uses defender's stats as attacker
   - Counter uses 10 base damage (not Quick/Normal base)
   - Counter pattern is Quick (3×1) or Normal (3×2) based on Counter type selected
   - Counter applies all bonuses: Facing, Bounce, Pattern, Haki, Alloys
3. If defender dies from initial damage, counter does not trigger

### 14.4 Defender Bonus Conversion
Defender has same access to Facing Direction, Pattern, and Bounce bonuses. **During defense phase**, offensive bonuses split into **BOTH** dodge chance AND damage reduction:

**Defense Phase Conversion** (Evade/Defend/Tank/Counter defensive portion):

| Bonus Type | Max Offensive | Defense Dodge Bonus | Defense Damage Reduction |
|------------|---------------|---------------------|-------------------------|
| **Facing Direction** | 15% | **+15% dodge** | **+15% dmg reduction** |
| **Bounce** | 25% → 10% | **+10% dodge** (40% of 25%) | **+10% dmg reduction** |
| **Pattern** | 25% → 12.5% | **+12.5% dodge** (50% of 25%) | **+12.5% dmg reduction** |

**Conversion Rules**:
- **Defense phase**: Bonuses become dodge chance AND damage reduction simultaneously
- **Counter offensive phase**: After surviving damage, counter-attack uses bonuses normally (+hit, +damage)
- Dodge bonus applies to hit chance calculation (reduces attacker's hit chance)
- Damage reduction applies to damage calculation (reduces final damage taken)

## 16. TYPE ADVANTAGE & NULLIFICATION

### 16.1 Multiplier Range Definition
Each Devil Fruit type interaction defines a **multiplier range**:
- **Advantage ("vs")**: Range is **1.0 to MAX** (e.g., 1.0 → 1.5)
- **Disadvantage ("weak_vs")**: Range is **MIN to 1.0** (e.g., 0.5 → 1.0)

### 16.2 Attacker Multiplier Calculation
```python
attacker_mastery = attacker.devil_fruit_mastery / 100.0  # 0.0 to 1.0

if is_advantage:
    # Scale FROM 1.0 TO the max multiplier
    damage_mult = 1.0 + (max_damage_multiplier - 1.0) × attacker_mastery
    speed_mult = 1.0 + (max_speed_multiplier - 1.0) × attacker_mastery

elif is_disadvantage:
    # Scale FROM min multiplier TO 1.0
    damage_mult = min_damage_multiplier + (1.0 - min_damage_multiplier) × attacker_mastery
    speed_mult = min_speed_multiplier + (1.0 - min_speed_multiplier) × attacker_mastery
```

### 16.3 Defender Multiplier Calculation
Defender's mastery **reduces** the attacker's advantage/penalty:
```python
defender_mastery = defender.devil_fruit_mastery / 100.0  # 0.0 to 1.0

# Defender's mastery provides up to 50% mitigation of attacker's multiplier effect
counter_strength = 1.0 - (0.5 × defender_mastery)  # Range: 1.0 → 0.5

# Apply counter-effect to final multiplier
final_damage_mult = 1.0 + (attacker_damage_mult - 1.0) × counter_strength
final_speed_mult = 1.0 + (attacker_speed_mult - 1.0) × counter_strength
```

### 16.4 Effective Stat Calculation
```python
# For damage calculation:
effective_strength = attacker.strength × final_damage_mult
effective_defense = defender.defense  # If defender is disadvantaged, this is unchanged

# For hit chance calculation:
effective_speed = attacker.speed × final_speed_mult
effective_reaction = defender.reaction  # If defender is disadvantaged, unchanged
```

### 16.5 Devil Fruit vs Non-User
- If attacker has DF and defender does not:
  - Apply **default base advantage**: `damage_multiplier: 1.10`, `speed_multiplier: 1.05`
  - These follow the same mastery scaling rules as type advantages
- If both lack DF: No DF nullification occurs; use base stats directly

### 17.4 Resistance Application

**Resistance Formula**:
```python
FinalMagnitude = CalculatedMagnitude × defender.effect_resistance[type] × (defender.df_mastery / 100)

# Example:
# - Fire user (burn: 0.0) at 80 mastery hit by burn DoT (calc 5)
#   = 5 × 0.0 × 0.80 = 0 (immune)
# 
# - Ice user (freeze: 0.5) at 60 mastery hit by freeze instant (calc 10)
#   = 10 × 0.5 × 0.60 = 3 damage
```

**Cap**: Final magnitude cannot be negative. Minimum is 0.

### 17.2 Effect Application from Trap Tiles
When an enemy enters a trap tile:
1. Trap tile is **destroyed immediately**
2. Effect is applied to the enemy per formulas in 17.3
3. Duration countdown begins **from the turn of activation**
4. Effect persists for its defined duration regardless of subsequent movement

### 17.3 Effect Application from Attacks
When an attack with an associated effect hits:
1. Effect is applied to the target per formulas in 17.3
2. Duration countdown begins from the **next turn** (attack effects apply post-damage)
3. If attacker has disadvantage, effect may be applied to **self** instead
4. Effect magnitude and duration scale with attacker's `devil_fruit_mastery`

## 18. DYNAMIC DEFENSIVE STAMINA COST

### 18.1 Core Mechanism
- **Base multiplier**: +25% stamina cost for all defensive planning movements

### 18.2 Hit Chance Tax Formula
```python
# Defense stamina cost calculation
base_multiplier = 1.25  # +25% for all defensive actions

# FOV Stamina Modifier (Defense Phase - see Section 31)
fov_stamina_mod = 1.0  # Default
defender_fov_layer = get_fov_layer(defender.facing, defender_position, attacker_position)
if defender_fov_layer == "FOV":
    # Defender sees attacker coming
    defense_action_discount = 0.70  # -30% for defense actions (Evade/Defend/Counter/Tank)
    movement_discount = 0.85  # -15% for movement
elif defender_fov_layer == "Behind":
    # Defender is blind-sided
    movement_penalty = 1.15  # +15% for movement
    # Defense actions: no special discount
else:
    # Periphery: neutral
    pass

# Hit chance tax (NEW BASE: 66%)
hit_chance_tax = max(0.0, (AttackerFinalHitChance - 0.66) × 2.0)
hit_chance_tax = min(hit_chance_tax, 0.25)  # Cap at +25%

# Total stamina multiplier (FOV modifier applied before tax)
total_stamina_multiplier = base_multiplier * fov_stamina_mod + hit_chance_tax

# Observation Haki discount (applies to entire defense phase)
if observation_haki_active:
    total_stamina_multiplier *= 0.85  # -15% cost

# Final cost
FinalStaminaCost = BaseActionCost × total_stamina_multiplier
```

- **If Attacker_Rate > 66%**: Defender pays +2% stamina per +1% hit chance above 66%
- **If Attacker_Rate < 66%**: Defender gets -2% stamina per -1% hit chance below 66%
- **Tax Cap**: +25% maximum (attacker hit ≥78.5%)
- **Observation Discount**: -15% total cost if Observation Haki active

### 18.3 Hit Chance Tax Examples
- Attacker's Final Hit Chance includes: **Base 66%** + Attack type mod (±25%) + Defense type mod (±25%) + Facing Direction (max +15%) + Bounce (max +10%) + Pattern (max +25%) + Stats + Haki
- **Example 1**: 66% + 25% (Facing) + 10% (Bounce) + 25% (Pattern) = 126% → capped at 95%
  - Tax: (95% - 66%) × 2 = 58% → capped at 25%
  - Total multiplier: 1.25 (base) + 0.25 (tax) = 1.50 (50% stamina cost)
- **Example 2**: 66% - 25% (Evade) = 41%
  - Tax: (41% - 66%) × 2 = -50% → max(0%, -50%) = 0%
  - Total multiplier: 1.25 + 0.0 = 1.25 (25% stamina cost)
- **With Observation Haki**: Final multiplier × 0.85

## 20. TILE TYPE SPECIFICATIONS

### 20.1 Unpassable Tiles
- **Effect**: Blocks all movement (cannot walk on or push through)
- **Visual**: Dark grey stone tile with "X" symbol

### 20.2 Trap Tiles (Continuous & Momentary)

**Debuff Types** (random 10-20% magnitude, 1-3 turn duration after stepping off):
- **Health**: Instant -X% health OR Poison: -X% health per turn for N turns
- **Stamina**: Instant -X% stamina OR Multiplier: +X% stamina cost for all actions
- **Damage**: Take +X% damage OR Deal -X% damage
- **Hit Chance**: Your hit chance -X% OR Enemy hit chance +X% against you

**Continuous Trap**
- **Duration**: Permanent (entire battle)
- **Interaction**: Debuff applied; tile remains
- **Visual**: Purple tile with skull symbol (solid)

**Momentary Trap**
- **Duration**: 1-3 turns, then disappears automatically OR when stepped on
- **Interaction**: Debuff applied; **tile disappears immediately**
- **Visual**: Purple tile with clock symbol (pulses when about to disappear)

### 20.3 Drop Tiles (Continuous & Momentary)

**Continuous Drop**
- **Effect**: Instant restoration when stepped on:
  - Health Drop: +20 health (capped at max)
  - Stamina Drop: +30 stamina (capped at max)
- **Interaction**: **Tile disappears immediately when stepped on**
- **Visual**: Green tile with plus symbol (+) (solid)

**Momentary Drop**
- **Duration**: 1-3 turns, then disappears automatically OR when stepped on
- **Effect**: Same buffs as Continuous Drop
- **Interaction**: Buff applied; **tile disappears immediately**
- **Visual**: Green tile with plus symbol (+) (pulses when about to disappear)

## 21. SEA TILES (DOOM MECHANIC)

### 21.1 Spawn Mechanics
- **Activation**: 20% chance at battle start; **NO per-turn spawn**
- **Location**: Edges of 7×7 board (not on squares)
- **Group Structure**:
  - 1 to 4 groups per edge (North, East, South, West)
  - Each group: **4 to 7 tiles** in contiguous row/column
  - **Corner Rule**: If corner square has sea tiles from both edges, **third corner sea tile created** to connect row and column

### 21.2 Game Over Condition
- **Pushed into Sea Tile**: Immediate Game Over for that player
- **Simultaneous Push**: Both players = Draw
- **Voluntary Movement**: Invalid move (blocked)
- **NO Push Damage**: Players take **zero extra damage** from being pushed into sea tiles

### 21.3 Sea Tile Interactions
- **Cannot be moved onto voluntarily**: Game prevents this action
- **Cannot be destroyed**: Indestructible (∞ HP)
- **Cannot be attacked**: Invalid action (no targeting)
- **Strategic Value**: Forces central combat; enables diagonal corner push checkmates

## 22. SPECIAL TILE DAMAGE & DESTRUCTION

### 22.1 Damage Application

**Attack Damage (NO strength multiplier)**:
- **Tile_Damage** = Base_Attack_Damage × (1 + Facing_Bonus + Bounce_Bonus + Pattern_Bonus)
- Base_Attack_Damage: Quick = 10, Normal = 20, Heavy = 30

**Push Collision Damage (WITH strength multiplier)**:
- **Push_Damage** = Base_Push_Damage × (1 + Facing_Bonus + Bounce_Bonus + Pattern_Bonus) × (1 + strength/400)

- **Applies to**: Continuous Trap, Momentary Trap, Drop Tiles, Internal Walls

### 22.2 Destruction Threshold
When tile HP reaches 0:
- **Tile is removed from battlefield**
- **If tile was occupied**: Tile removed; **player remains in place** (no ejection, no damage, no stun)

### 22.3 Tactical Destruction
- **Destroy Drop Tile**: Wastes buff (denies opponent)
- **Destroy Trap Tile**: Removes threat
- **Destroy Wall**: Opens paths
- **Sea Tiles**: Cannot be destroyed or targeted

## 29. COMPLETE COMBAT RESOLUTION FLOW

### 29.1 Attack Resolution with Full DF Integration
```python
# 1. Check DF nullification
effective_att_str, effective_def_def, effective_att_spd, effective_def_rea = calculate_effective_stats(attacker, defender)

# 2. Calculate base hit chance (purely difference‑based stats)
hit_chance = 50%
           + (effective_att_spd - effective_def_rea) × 0.15%
           + (combat_instinct difference) × 0.15%
           + (aura - willpower) × 0.10%
           + FacingDirectionBonus
           + BounceBonus
           + PatternBonus

# 3. Apply Haki alloys if present
if attacker.observation_haki_active:
    hit_chance += 30% × ObservationEffect

# 4. Clamp hit chance
final_hit_chance = max(5%, min(95%, hit_chance))

# 5. Determine if attack hits
if random() ≤ final_hit_chance:
    # Calculate damage
    damage = BaseDamage
           × (1 + (effective_att_str - effective_def_def) × 0.15%)  # StatModifier
           × (1 + (aura - willpower) × 0.15%)                       # Aura/Willpower (difference only)
           × (1 + FacingBonus + BounceBonus + PatternBonus)        # Position bonuses
           × (1.30 × ArmamentEffect if Armament active)            # Haki alloy
    # Apply DF effect if present
    apply_status_effect(attacker.fruit.effect, defender)
else:
    # Attack misses, no damage
```

### 29.2 Defense Resolution with DF Integration

## 31. FIELD OF VIEW (FOV) SYSTEM

### 31.1 FOV Layer Architecture

The battlefield is divided into three perpetual vision layers relative to each player's facing direction.

**Layer 1: FOV (Front Arc)** - 180° arc directly in front
**Layer 2: Periphery (Side Arcs)** - 90° total (45° left and 45° right)
**Layer 3: Behind (Rear Arc)** - 180° arc directly behind

### 31.2 FOV Combat Bonuses

**Attacker Hit Chance Bonus (Attack Phase):**
- FOV layer: 0% (no bonus)
- Periphery layer: +10% (flanking)
- Behind layer: +30% (rear attack surprise)

**Defender Stamina Modifiers (Defense Phase):**
- FOV layer: -30% defense actions, -15% movement (sees attack coming)
- Periphery layer: no change (neutral)
- Behind layer: +15% movement, -20% Counter success (blind-sided)

### 31.3 Observation Haki Override

When defender activates Observation Haki:
- Attacker's FOV hit bonus negated to 0%
- Counter gets +20% success chance

### 31.4 FOV Summary

| Layer | Attacker Hit | Defender Defense Cost | Defender Move Cost | Counter Penalty |
|-------|--------------|----------------------|-------------------|----------------|
| FOV | 0% | -30% | -15% | None |
| Periphery | +10% | 0% | 0% | None |
| Behind | +30% | 0% | +15% | -20% success |
