                    BATTLE TIMER SYSTEM - IMPLEMENTATION PLAN
═══════════════════════════════════════════════════════════════════════════════

OVERVIEW:
─────────
Implement 45-second turn timer with server-authoritative validation, grace period
for connection verification, flag system (3 strikes = forfeit), and client-side
countdown display.

KEY DESIGN DECISION:
────────────────────
Use CONFIRMATION VALIDATION pattern - player clicks Confirm → server validates
timing → server approves/rejects → existing pipeline proceeds/skips.

This prevents race conditions where late combat data arrives after skip processed.

NEW MESSAGE HANDLER: "turn_confirm_request"
───────────────────────────────────────────

LOGIC:
1. Extract lobby_id, session_id, turn_number from message
2. Check if (lobby_id, turn_number) exists in lobby_turn_timers
3. Calculate elapsed = time.time() - lobby_turn_timers[(lobby_id, turn_number)]
4. If elapsed <= 45.0:
   → Send "turn_confirm_approved" to requesting player
   → Mark lobby_turn_confirmed[(lobby_id, turn_number)][session_id] = True
5. Else (timeout):
   → Send "turn_confirm_rejected" with reason="timeout" to requesting player
   → Increment lobby_player_flags[(lobby_id, session_id)] += 1
   → Broadcast "skip_turn" to both players with flag count
   → Check if flags >= 3 → trigger forfeit
   → Start grace period tracking for connection verification
